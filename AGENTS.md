# Project

`b14_client` (PizzaHub): single-package Next.js **16.4.6** App Router app, React 19, TypeScript strict. Not a monorepo; package manager is **npm**. No tests, no CI, no ESLint/Prettier — Biome is the only linter/formatter.

## Commands

- `npm run dev` — `next dev` (Turbopack)
- `npm run build` — `next build`; runs TypeScript; regenerates `.next` and `next-env.d.ts`. Building needs network on a cold font cache (`next/font/google` downloads Plus Jakarta Sans + Fredoka)
- `npm run start`, `npm run lint` (`biome check`), `npm run format` (`biome format --write`)
- No `test` script. Typecheck separately: `npx tsc --noEmit` (currently passes); `npm run build` typechecks too
- **`npm run lint` currently exits 1 on the existing tree** (~150 findings incl. unsorted imports, style, a11y; `src/components/ui/*` generated by shadcn is not Biome-formatted). Don't treat a clean `lint` as a gate

## Layout

- `src/app` — App Router. Real routes today: `/`, `/signin`, `/signup`, `/not-found`, `/api/auth/[...all]`. `Navbar` links to `/menu`, `/dashboard`, `/profile`, which **don't exist yet**
- Import alias `@/*` → `src/*`. `cn` helper: `@/lib/utils` re-exports `cn` from the `cn` package; generated ui files import `cn` from `"cn"` directly
- `src/components/ui` — ~60 shadcn-generated components (`components.json`, shadcn v4, style `base-nova`). **Base UI, not Radix** (`@base-ui/react`): use `render={<Link .../>}` instead of `asChild`, `nativeButton={false}` when rendering non-`<button>`; add components via `npx shadcn add`. Don't mass-reformat generated `ui/` files
- `src/components/Navbar.tsx`, `src/app/globals.css`, `src/assets`. `src/lib/highlighter.tsx` + `src/hooks/use-highlighted-code.ts` — shiki syntax highlighting (grammar-state streaming); `src/hooks/use-mobile.ts`
- Next 16: `LayoutProps<"/">` in `src/app/layout.tsx` is a generated global type; `next-env.d.ts` is gitignored. `reactCompiler: true` in `next.config.ts` (React Compiler); Tailwind v4 via `@tailwindcss/turbopack`, no `tailwind.config`

## Styling

Tailwind CSS v4: `src/app/globals.css` does `@import "tailwindcss"` + `tw-animate-css` + `shadcn/tailwind.css`, `@theme`/`@custom-variant`; **dark mode = `.dark` class**, not `prefers-color-scheme`; `data-theme="light"` on `<html>`; `components.json` aliases under `@/...`.

## Auth

better-auth v1.7 + `@better-auth/mongo-adapter` + `mongodb`:

- Server `src/lib/auth.ts`; client `src/lib/auth-client.ts` (`signIn`, `signUp`, `useSession`, `authClient.signOut`...); catch-all handler `src/app/api/auth/[...all]/route.ts`
- MongoDB database name hardcoded `b14_client`; email+password enabled; Google social provider; `jwt()` plugin + `jwtClient()`. **`admin()` / `adminClient()` and `inferAdditionalFields` are commented out** — client `session.user.role` isn't typed
- `user.role` additional field: `"customer" | "vendor" | "admin"`, default `"customer"`, `input: true`
- `src/lib/auth-client.ts` currently imports server `auth` (unused; `inferAdditionalFields<typeof auth>()` commented out). Keep new client usage `import type`, and don't assume `src/lib/auth.ts` code is excluded from client bundles unless verified

## Environment

Next loads `.env` (shown as `Environments: .env` at build). **`.env*` is gitignored and untracked**; a local `.env` is required. No secrets in commits. Vars read by app code or its auth library:

- `MONGODB_URL`
- `BETTER_AUTH_SECRET` (consumed by better-auth; required, throws if missing/default in production)
- `BETTER_AUTH_URL` (`authClient` baseURL; app origin e.g. `http://localhost:3000`)
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — if unset, build warns `Social provider google is missing clientId or clientSecret` and Google sign-in won't work
- `BASE_URL` may exist in `.env` but **no code reads it**
